# NexysDraft draft5i 보고서 — 빠른 클릭·드래그에서 클릭이 씹히는 문제 → v0.4.9

2026-11-11. 사용자 보고: "클릭이 씹히는 경우가 많다. 보통 CAD는 클릭·드래그를 빠르게 반복해도 다 찍힌다."

## 원인과 수정
| 원인 | 수정 |
|---|---|
| 객체 선택을 마우스 버튼을 **뗄 때** 판정했고, 누른 자리에서 4 px만 움직여도 드래그 상자로 봤다. 급한 클릭은 몇 px 미끄러지므로 아주 작은 창 선택이 되어 아무것도 안 잡히고 기존 선택까지 풀렸다. | 버튼을 **누르는 순간** 커서 아래 객체를 선택한다(AutoCAD와 같음). 자르기·연장·간격띄우기의 객체 지정도 같다. 클릭/드래그 구분은 6 px. |
| 위 수정만 하면 객체 위에서 시작하는 상자 드래그가 안 된다(빽빽한 도면). | 객체 위에서 눌렀더라도 200 ms 이상 누르고 있었거나 24 px 이상 끌었으면 상자 선택으로 본다. |
| 캔버스를 클릭할 때마다 툴바·상단 바·파일·레이어 패널을 통째로 다시 만들었다. 버튼을 누르고 떼는 사이에 다시 만들어지면 그 클릭은 사라진다. | 내용이 달라졌을 때만 다시 만든다. |
| 레이어 패널이 클릭마다 도면의 모든 객체를 세었다. | 도면이 바뀔 때만 센다. |
| 창 전환 등으로 시스템이 포인터를 가져가면 끌던 상태가 남았다. | pointercancel에서 정리. 캔버스에 user-select / touch-action none. |

점 지정(선 그리기 등)은 원래 누르는 순간에 받았다 — 바뀐 것 없음.

## 확인하지 못한 것 (UNVERIFIED)
- 사람 손으로 빠르게 조작했을 때의 체감. 자동 시험은 이벤트를 쉼 없이 넣어 확인한 것이다.
- 수정 전 빌드로 같은 시험을 돌려 실패를 재현하지는 않았다(코드상 4 px 이상이면 창 상자가 되는 것은 확정).
- dotnet 단위 시험은 이번에 다시 돌리지 않았다(엔진 코드 변경 없음, 화면 코드와 셀프테스트만 변경).

## 남은 동작 (AutoCAD와 같게 둔 것)
- 빈 곳을 클릭하면 선택 상자가 열리고, **다음 클릭이 상자의 반대쪽 모서리**가 된다. 객체를 노렸다가 빗나간 클릭 다음의 클릭은 그래서 상자를 닫는 데 쓰인다. 선택 허용 범위는 8 px.
