# 블록별 회고 (됐나 / 막혔나 / 다음 조정)

## draft5 (2026-10-31)

### I1 — AutoCAD 조작
- **됐나**: 점 입력을 "객체 스냅 → 그리드 스냅 → 직교/극좌표" 한 함수(`effectivePoint`)로 모았다. 클릭, 고무줄 미리보기, 직접 거리 입력이 같은 규칙을 써서 관문이 첫 실행에서 통과했다. 작업 중에 Enter/Space가 두 리스너에서 두 번 처리되던 결함도 찾았다.
- **막혔나**: 정규식을 Python heredoc으로 넣다가 백슬래시가 한 번 더 빠졌다(메모의 그 문제). 정규식 리터럴로 바꾸고 Edit 도구로 고쳤다. DI 관문은 명령줄 기록이 3줄만 남아서 처음에 실패했다. 테스트용 전체 기록(log)을 따로 두었다.
- **다음 조정**: 소스에 정규식이나 백슬래시를 넣을 때는 처음부터 Edit/Write 도구를 쓴다.

### I2/I3/I4
- **됐나**: 캔버스 색을 CSS 토큰으로 옮겨 앱 테마와 분리했다. 대비는 캡처 PNG의 픽셀로 쟀다. PDF는 "개별 = 합본의 쪽마다"로 규칙을 정하자 u05(시트 9 + 나머지 1)와 u01(시트 감지 안 됨)이 둘 다 맞았다.
- **막혔나**: 지시서는 u05를 "시트 10개"로 보았지만 실제는 시트 9개에 나머지 1쪽이었다. 캡처를 보다가 레이어 견본이 캔버스 테마를 따르는 실수를 찾아 고쳤다.
- **다음 조정**: 관문 숫자의 근거(시트 수 같은)는 구현 전에 측정해서 확인한다.

## draft4 (2026-10-30)

### H0 — 글꼴 매트릭스
- **됐나**: 매트릭스 DWG를 ODA로 읽었더니 xdata가 `_APP12`에 붙어 있었다. 이것을 따라가 dxf2dwg가 ACAD xdata를 핸들 0x12로 고정해 쓴다는 것을 dwgread JSON으로 확정했다. u04 DWG가 draft3부터 같은 상태였다는 것도 함께 드러났다.
- **막혔나**: 처음에 APPID 표 순서를 바꾸는 것으로 고쳤는데, 매트릭스에서만 맞고 u04에서는 효과가 없었다. 두 도면에 같은 실험을 돌리고 나서야 "항상 0x12"라는 규칙이 보였다. draft3에서 이 결함을 놓친 이유는 `tools/oda.py`가 `x.dwg`와 `x.dxf`의 결과를 같은 이름으로 써서 덮어썼기 때문이다.
- **다음 조정**: 한 도면에서 통한 수정은 다른 도면(사용자 도면 1개 이상)에도 적용해 보고 확정한다. 검증 도구의 출력 이름은 입력 확장자까지 포함한다.

### H1/H2/H3
- **됐나**: 버전 선택을 Core의 `DxfSave` 하나에 두고 앱·CLI·관문이 같은 규칙을 쓰게 해서 관문 7/7을 한 번에 통과했다. 그러다 R2000 저장에 쓰던 u04의 `^` 이스케이프 결함도 찾았다(이름 없는 블록 안의 SHX 한글이라 R2000에서는 원래 빠지고, DXF 원본 유지 경로에서 확인).
- **막혔나**: 10만 열기 측정이 다른 프로그램의 부하(CPU 52 %)로 2.1~3.8 s 사이를 오갔다. v0.3.0과 번갈아 재서 회귀가 아님을 보였다. 스킬 테스트는 `--out`에 상대 경로를 주면 자식 프로세스가 경로를 두 번 붙여 실패했다(고침).
- **다음 조정**: 성능 관문은 부하를 기록하고 같은 조건의 기준 빌드와 번갈아 잰다.
